# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

FUTO Keyboard: an offline Android keyboard forked from AOSP LatinIME, heavily modified (Compose UI, YAML layouts, transformer language model, Whisper voice input, Chinese/Japanese engines). Mixed Java (mostly AOSP-derived) and Kotlin (mostly new code), plus C++ via JNI.

## Build & test

Submodules are required (prebuilt AARs in `libs/`, layouts, translations, themes, large resources, ML models). A plain clone will not build:

```
git submodule update --init --recursive
```

Build (the root project is the app module; `voiceinput-shared` is the only subproject):

```
./gradlew assembleUnstableDebug        # default dev flavor
./gradlew assembleStableRelease
./gradlew bundlePlaystoreRelease
./gradlew lintUnstableDebug            # config: lint.xml, baseline: java/lint-baseline.xml
```

`python3` must be on PATH: `preBuild` runs the `updateLocales` task (see Generated code below). Requires NDK `28.2.13676358`; native code builds through CMake (`native/jni/CMakeLists.txt`) as part of the Gradle build.

Tests are instrumented only (source set `androidTest` → `tests/src`, `tests/res`, `tests/AndroidManifest.xml`), so they need a device/emulator:

```
./gradlew connectedUnstableDebugAndroidTest
./gradlew connectedUnstableDebugAndroidTest -Pandroid.testInstrumentationRunnerArguments.class=org.futo.inputmethod.latin.SomeTest
./gradlew connectedUnstableDebugAndroidTest -Pandroid.testInstrumentationRunnerArguments.class=org.futo.inputmethod.latin.SomeTest#testMethod
```

`native/jni/run-tests.sh` and `tools/dicttool/Android.bp` are AOSP leftovers that need an AOSP build tree; they don't work from Gradle.

## Flavors and source sets

Non-standard layout, configured in `build.gradle` `sourceSets`:
- Java/Kotlin: `common/src` + `java/src`, plus flavor dirs `java/stable/java` (stable & unstable) or `java/playstore/java` (playstore).
- Manifest: `java/AndroidManifest.xml`, with flavor manifests in `java/stable/` and `java/playstore/`.
- Resources: `java/res` (English source strings), `java/res-large` (submodule), and translations filtered from the `translations/` submodule at build time.

Flavors: `unstable` (default, `.unstable` app id suffix, extra dev strings from `java/unstable/res`), `stable`, `playstore` (no update checking, Google Play pricing). CI fails stable/playstore builds if the merged manifest contains `android.permission.INTERNET`. Keep the app offline; don't add that permission or dependencies that pull it in.

Build-time `BuildConfig` fields (`IS_PLAYSTORE_BUILD`, `UPDATE_CHECKING`, `ENABLE_ACRA`, payment URLs) differ per flavor. Optional `keystore.properties` / `crashreporting.properties` at the root enable release signing and ACRA; without them the build still works.

## Generated / externally owned files

- `java/src/org/futo/inputmethod/keyboard/internal/KeyboardTextsTable.java` is generated by `tools/make-keyboard-text-py/src/generate.py` from the JSON in `tools/make-keyboard-text-py/locales/` (per-language morekeys and symbols). Edit the JSON; the table regenerates on every build.
- Non-English `values-*` strings come from the `translations/` submodule (managed in Pontoon; CI syncs `java/res/values/strings*.xml` outward). Only add or edit English strings in `java/res/values`, `java/unstable/res/values` or `voiceinput-shared/src/main/res/values`.
- Keyboard layouts are YAML in `java/assets/layouts/` (submodule of the separate futo-keyboard-layouts repo, which has `mapping.yaml` for locale→layout and `names.yaml`).
- `.../uix/settings/pages/credits/Contributors.kt` is produced by the `updateContributors` task.
- Mozc (Japanese), RIME (Chinese) and FUTO swipe ship as prebuilt AARs in `libs/`.

## Architecture

**Service and engine split.** `latin/LatinIME.kt` is the `InputMethodService`, which also hosts Compose (lifecycle, view model and saved-state owners). It still wraps `LatinIMELegacy.java`, the remains of the AOSP service. Text processing goes through `engine/IMEManager.kt`, which picks an `IMEInterface` implementation (`IMEKind`) for the current subtype:
- `engine/general/GeneralIME.kt` handles alphabetic languages and drives `latin/inputlogic/InputLogic.java` (AOSP input logic: composing, autocorrect, space state), dictionaries and suggestions.
- `ChineseIME.kt` uses RIME, `JapaneseIME.kt` uses Mozc.
- `ActionInputTransactionIME` lets actions (such as voice input) take over input temporarily.

**Keyboard layouts (v2keyboard).** `v2keyboard/LayoutManager.kt` loads the YAML layouts from assets. `LayoutEngine.kt` and `KeyboardSizingCalculator.kt` compute key geometry and sizing modes (docked, split, one-handed, floating). The output feeds the legacy AOSP `keyboard/` package (`KeyboardSwitcher`, `MainKeyboardView`, `PointerTracker`, `ProximityInfo`), which still does rendering and touch tracking. `event/` holds the event and combiner chain (dead keys, Hangul, etc.).

**UIX layer.** `latin/uix/` holds the newer Compose UI. `UixManager.kt` owns the action bar, suggestion bar and action windows. Actions are `Action` objects registered in `uix/actions/Registry.kt` `AllActionsMap`. Key codes derive from the index in that map (`CODE_ACTION_0 + index`), so **only append; never reorder or remove entries**. Themes live in `uix/theme/`; the settings UI (navigation-compose) lives in `uix/settings/` with pages under `pages/`.

**Settings.** There are two systems. New settings are `SettingsKey<T>` (DataStore preferences) defined near their feature, read with `context.getSetting(...)`, `getSettingBlocking` or `useDataStore` in Compose (`uix/Settings.kt`, `uix/settings/Hooks.kt`). Legacy AOSP settings are SharedPreferences, exposed through `latin/settings/Settings` and `SettingsValues`. The keyboard can run before the device is unlocked (direct boot): DataStore is unavailable until then, so check `isDirectBootUnlocked` and the existing unlock handling before reading settings or user data at startup.

**Prediction.** `latin/xlm/` holds the on-device transformer language model (`LanguageModel.kt`, `LanguageModelFacilitator.kt`), which combines LM output with AOSP binary dictionaries (`DictionaryFacilitator*`). `AdapterTrainer` and `TrainingWorker` do on-device fine-tuning. Models are managed in `ModelPaths.kt`.

**Native (`native/jni`).** One `libjni_latinime` library contains the AOSP dictionary and suggestion engine (`src/dictionary`, `src/suggest`), GGML, sentencepiece, and Whisper. JNI glue files are named after their Java/Kotlin class (for example `org_futo_inputmethod_latin_xlm_LanguageModel.cpp`). Native source files are listed in `NativeFileList.cmake`. Native code always compiles with optimization because GGML is unusably slow without it.

**Voice input.** The `voiceinput-shared/` library module holds Whisper-based recognition (`AudioRecognizer`, `ggml/WhisperGGML.kt`, `whisper/`). Its models come from the `voiceinput-shared/src/main/ml` submodule. The keyboard side is `uix/actions/VoiceInputAction.kt`.

## Project conventions

- The minimum SDK is 24 with core library desugaring. Java/Kotlin target is 1.8.
- Upstream (FUTO GitLab, mirrored to GitHub) requires a CLA for PRs and states it does not accept AI-generated pull requests. Layout contributions go to the separate futo-keyboard-layouts repo.
- Version code and name come from `git rev-list --first-parent --count master` and `git describe --tags`, unless `VERSION_CODE` or `VERSION_NAME` env vars are set.
